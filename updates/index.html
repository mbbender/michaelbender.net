WHAT THIS MEANS FOR YOUR BUSINESS

Your website can look normal.
The server still needs checking.

PHP is software that runs behind many websites, online stores, and custom business tools. The two flaws, often called PHP2Shell, can let an attacker run commands on an affected server without logging in. They could put your website and its data at risk.

The issue is in PHP itself. Updating a page or changing your website password does not install the server fix.

Start with your hosting provider.

Ask: “Have the fixes for CVE-2026-109618 and CVE-2026-109619 been applied to the PHP software serving our website?” If they confirm everything is covered, you may not need additional work.

If the answer is unclear, your software is old, or you no longer have a developer, I can help you understand the situation and agree on a practical plan.

FOR YOUR DEVELOPER OR HOST

The technical details,
when you need them.

Which PHP versions and fixes should we check?
  • Fixed PHP releases: 8.5.12, 8.4.27, 8.3.36, and 8.2.35.
  • All PHP installations serving web requests are considered at risk, including PHP-FPM, Apache with mod_php, php-cgi, FrankenPHP, and LiteSpeed. PHP identifies the highest demonstrated risk with mod_php.
  • For PHP 8.1 and older, check vendor-provided backported packages. The PHP team also supplied minimal source backports for 7.4, 8.0, and 8.1. These do not restore ongoing support for those branches.
  • Check the runtime actually serving each application, including bundled PHP in containers or appliances. A version number alone may not show a vendor's backported fix.
  • PHP's temporary mitigations address specific paths. They do not replace the update.
